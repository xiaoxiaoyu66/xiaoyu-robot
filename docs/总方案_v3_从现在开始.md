## 2. S4 · 记忆：三级台阶

**总原则**：v2 把 S4 当一大步，v3 拆成三个独立验收的小台阶。
做完 4a + 4b 就有 80% 的「陪伴感」，4c 是锦上添花——随时可以停在任何一个台阶。

### 4a · 重启不失忆（1 次开工）

**目标**：关掉程序再开，它记得昨天聊到哪。

**前置**：动手前先真机验证一次「接续对话」（唤醒后连聊 3 轮，TODO 里挂着的那条）——
4a 改的就是同一段循环逻辑，先验现状再改，出了问题才知道是谁引入的。

**改什么**：
1. `DeepSeekClient` 启动时把 `memory.recent_messages(settings.llm.max_history)` 读回 `_history`
   ——数据已经在库里了，现在只是没人读回来（`HANDOFF.md` §6.1）
2. system prompt 注入时间感：当前日期时间 + 上次对话的收尾时间（查 `messages` 表最后一条 `created_at`）
3. 决定并落实：`--text` 键盘模式写不写记忆（建议也写，行为一致好排查）
4. API 失败要「说」出来而不是静默：余额不足、断网时让 TTS 说一句
   「我这会儿连不上脑子了」——体感从故障变成性格，只改 `stream_reply` 的异常分支
5. 顺带加最土的备份：启动时把 `data/xiaoyu.db` 复制一份 `xiaoyu.db.bak`（一行 shutil 的事）
   ——S4 之后这个库就是它全部的记忆，硬盘一坏就是失忆

**验收**：今天说「我下周三要交简历」→ 关程序 → 重开问「我最近有啥事」→ 它答得上来，并且知道今天几号。

**卡住怎么办 / 兜底**：
- 时间感不对 → `datetime.now()` 每轮现取，别启动时取一次存着
- 读回的历史把 prompt 撑爆 → 只读回最近 N 轮（N 就是现有的 `max_history`）
- **最后退路**：读回失败就退回「仅本次会话记忆」——这本来就是现状，不会更糟

### 4b · 事实积累（1 次开工）

**目标**：它主动记住「关于主人的事实」，而不是流水账。

**改什么**：`add_fact()` 已经写好了，缺的只是调用方——
每 `summarize_every`（20）轮，把最近的对话 + 已有 facts 一起交给模型：
「从对话里提取关于主人的新事实，已有的事实不要重复输出，JSON 数组返回」→ 去重后逐条 `add_fact()`。

**验收**：连续聊 20 轮（含个人信息）→ `facts` 表出现去重后的事实；再聊 20 轮不会把旧事实再记一遍。

**卡住怎么办 / 兜底**：
- 模型抽出来的 JSON 不合法 → 重试一次，再失败就跳过本轮，20 轮后再试
- 事实记错了 → SQLite 直接删行（`DELETE FROM facts WHERE id=...`），人可以修
- **最后退路**：整个抽取关掉，只留 4a——已有事实表为空不影响任何现有功能

### 4c · 向量检索（1～2 次开工，可选）

**技术路线（对 v2 的一处修订）**：v2 写的 `sentence-transformers` 会连带 2GB torch，
v3 改为**不引入 torch 的轻量路线**：

| 组件 | 选什么 | 为什么 |
|---|---|---|
| Embedding | **fastembed**（纯 ONNX，动手前先确认 `BAAI/bge-small-zh-v1.5` 在其支持列表）或 onnxruntime 直接加载 bge-small-zh 的 onnx 导出 | 模型 ~95MB，CPU 毫秒级，零 torch |
| 向量存储 | **现有 `vectors` 表就够**（`embedding BLOB`），检索时全量读出用 numpy 算余弦 | 个人规模（万条以内）毫秒级，不加任何依赖 |
| 向量数据库 | 不需要。以后量真大了再考虑 sqlite-vec | 个人项目别上服务化组件 |

**改什么**：
1. `remember_exchange()` 写库时顺带把 embedding 写进 `vectors` 表
2. `recall()` 从「最近 facts 占位」换成：查询向量 → numpy 余弦 top-k → 返回对应原文
3. 动手前先量：单条编码耗时（应该在 10ms 级）、1 万条全量余弦耗时（应该在个位数 ms）——量完再决定要不要 sqlite-vec
4. 顺手定增长策略：只对最近 90 天（或最近 1 万条）的 `messages` 建向量，更早的只留原文
   ——个人用一年也就几万条，不急，但策略在 4c 一次定掉，以后不用再想

**验收**：问「我最近有啥事」，命中的是**语义相关**的记录，而不是单纯最近的。

**卡住怎么办 / 兜底**：
- 模型下载卡住 → `HF_ENDPOINT=https://hf-mirror.com`；再不行用 fastembed 的镜像路径
- fastembed 不支持目标模型 → onnxruntime 手动加载（多写 20 行分词逻辑）
- **最后退路**：`recall()` 退化为「最近 N 条 facts」——4c 没做时它本来就是这么跑的，现状即兜底

|---|---|---|

## 3. S5 · 表情脸 + 触屏打断

### 3.1 协议先行（半天，这是脸和主控的唯一契约）

主控起一个 WebSocket 服务（Python 标准库之外只加一个 `websockets` 包），广播 JSON 事件：

```jsonc
{"type": "state",  "state": "idle"}        // idle / listening / thinking / speaking
{"type": "mouth",  "level": 0.37}          // 播放音量包络，50ms 一帧，口型跟随
{"type": "caption", "text": "今天也要加油"} // 可选：气泡字幕
```

要点：
- **`mouth.level` 是灵魂**。只靠 `speaking` 状态做口型是「假说话」；用播放中的音频按 50ms 窗口算 RMS 推帧，嘴就真的在动。实现上顺路把 `Speaker` 的 `sd.play` 换成 `OutputStream` 分块喂——天然得到 RMS 流，也天然得到 §3.2 要的 `stop()`
- **脸是纯消费者**：脸断线、没打开、手机锁屏，主流程一行代码都不改
- **安全边界**：旧手机要连它就得监听 `0.0.0.0`，那就只在家里 WiFi 用，**不映射公网**；
  加一个简单 token 校验（URL 参数或首条握手消息），防局域网里别的设备误连
- 状态事件的源头就是现有 `StateMachine.on_change()`，桥接层只有一个文件

### 3.2 触屏打断（比语音打断先做）

**为什么这个顺序**：语音打断要先解决回声（它说话时麦克风会听到自己），
触屏打断零硬件、零回声问题，且体验已经足够「像活的」。

**交互**：在脸上点一下 → 发 `{"type": "interrupt"}` → 主控停播 → 回 `LISTENING`。

**主控要预留的口子**（S4 期间可以先埋好）：
- `Synthesizer` 暴露 `stop()`：底层就是 `player.py` 里已有但没人调用的 `Speaker.stop()`
- 播放线程可查询「当前是否在播」，供状态机判断

**半双工铁律在打断时怎么保持**：停播 → 等 0.2 秒余音散掉 → 开麦。两行代码，别省。

### 3.3 脸本体

- Vue3 + **pixi-live2d-display** 起步（比直接啃 Cubism SDK 省一半时间），用现成模型，**不学建模**
- 屏幕设备随便选：旧手机 / **平板** / 笔记本浏览器窗口（期 C 硬件）——脸只是个网页，
  任何能开浏览器的设备都行，主控不关心它跑在什么上（同一 WiFi 即可）
- **保持亮屏**：安卓平板/手机开「充电时不锁屏」（或网页用 Wake Lock API）；iPad 把「自动锁定」设为永不
- **模型授权看一眼**：网上下载的 Live2D 模型很多标注「禁止再分发 / 仅限个人使用」，
  自用没事，但别把模型文件打包传上 GitHub

**卡住怎么办 / 兜底**：
- Live2D SDK 卡超过 1 小时 → 静态图 + CSS 动画顶替（v2 原话，依然有效）。协议不变，以后随时换真 Live2D
- 没有旧手机 → 笔记本上一个窗口，功能一样
- **最后退路**：整个 S5 不做，机器人保持纯语音——现状完整可用

## 4. S5.5 · 常驻自愈（N100 前置，1～2 次开工）

> 现在人在旁边，崩了重开就行。S6 要「开着不管」，这步就是为此补的。
> 放在 S5 之后是因为它不产生任何新体验，纯粹是可靠性投资。

**改什么**：

1. **主循环自愈**：`run_voice_loop()` 每轮包 try/except——记日志 → 等 2 秒 → 回待机；
   连续失败 5 次才退出，交给进程守护重启（退出原因写进 error.log）
2. **silero-vad 用起来，或删掉，不许继续挂空档**（二选一）：
   - 接上：sherpa-onnx 有现成 VAD 接口，模型已下载，替换 `recorder.py` 的固定阈值
   - 最简版：开机先采 0.3 秒噪声底，阈值 = 噪声底 × 系数，自适应环境
   - 为什么现在做：N100 挂的 USB 麦噪声底和笔记本完全不同，固定 0.015 大概率直接失效
3. **开机自启 + 进程守护**：Windows 用任务计划程序；N100 若装 Linux 则 systemd（`Restart=always`）
4. **电源计划**（笔记本常驻必做，N100 一样）：接通电源时永不睡眠、合盖不休眠——
   否则半夜它悄悄睡了，你还以为唤醒词坏了
5. **Windows 自动更新是常驻大敌**：设好「使用时段」，配合第 3 条的自启，
   更新重启之后能自己爬起来才算常驻
6. **误唤醒率要有数**：阈值 2.5 合不合适不靠感觉，靠数据——日志里已有「听到唤醒词」，
   每天扫一眼误唤醒次数（尤其夜里没人说话时它自己醒了几次），超过 1 次/天就调阈值

**验收**：跑起来之后拔插一次 USB 设备 / 断网一分钟，程序不退出，恢复后继续工作。

**卡住怎么办 / 兜底**：
- 自愈逻辑改出死循环 → git revert，守护先不上，人肉重启不影响任何功能
- **最后退路**：不上守护，每次手动开——现状

## 5. S6 · 眼睛 & 独立成体 = 「离开电脑」

> 目标形态说清楚：**不能动，但要离开电脑**——一个放在桌上、插电就活、
> 有自己的脸和声音的小机器人。这就是本方案的终点，而且架构从第一天就是照它设计的：
> 大脑在云端，本地只跑「耳朵 + 嘴」。

### 5.1 为什么可行（算力账本）

| 本地要跑的 | 模型大小 | 笔记本实测 | N100 预期 |
|---|---|---|---|
| 唤醒 KWS（常驻） | ~33MB | 几乎不占资源 | 无压力 |
| ASR SenseVoice int8 | ~166MB | 0.13~0.15 秒 | 0.3~0.5 秒，可接受 |
| 本地 TTS piper | ~100MB | RTF 0.06 | RTF 0.1~0.2，可接受 |
| 向量记忆（S4c） | bge-small ~95MB | 毫秒级 | 毫秒级 |

N100 是 x86，**代码零改动**——这是 v2 选它而不是树莓派的原因。结论：能做出来，
剩下的只是工程步骤和钱（期 D 预算 550～900 元）。

### 5.2 落地节奏：四个里程碑

| 里程碑 | 做什么 | 验收 |
|---|---|---|
| M1 | 笔记本常驻 7×24（S5.5 做完） | 连续跑一周不重启、拔插设备能自愈 |
| M2 | N100 到手，先当「第二台开发机」 | 装好 venv 环境，`bench_latency.py --no-llm` 出分 |
| M3 | 整体迁移 | 拷代码 → 装依赖 → 改两个设备名 → 跑通，行为和笔记本一致 |
| M4 | 外壳 / 支架 / 点头舵机（可选） | 纯手工活，不碰代码 |

**M2 的便宜验证法**：到手先别迁移，只跑 `python scripts\bench_latency.py --no-llm`，
ASR/TTS 耗时可接受（预期 <0.5 秒）再动手迁移；不行就退，损失为零。

### 5.3 N100 迁移清单

1. 依赖装进 venv，并 `pip freeze > requirements.lock` **锁死版本**
   ——现在的 `>=` 版本号在 N100 上复现不出同样的环境
2. 音频设备按**名字**配置（`XIAOYU_MIC_DEVICE_NAME`），别按编号——编号会漂移，devices.py 已做好按名字匹配
3. 验证 silero-vad / 自适应阈值在新麦克风上工作（§4 第 2 条的意义所在）
4. 拷走 `data/xiaoyu.db`——它的记忆跟着走

### 5.4 选型与形态

| 件 | 建议 | 原因 |
|---|---|---|
| 迷你主机 | N100 / 16G / 512G，**选无风扇** | 风扇声会毁掉「陪伴」感；整机 ~6~15W，24 小时开着电费每月几块钱 |
| 脸 | 旧手机 + 亚克力支架（期 C），和 N100 同 WiFi | S5 的 WebSocket 协议本来就是按「脸和本体分开」设计的 |
| 嘴 | 3.5mm 小音箱接 N100，音量固定 | 别走系统音效增强（加延迟、加杂音处理） |

### 5.5 两个别走的弯路（v2 的判断再钉一次）

1. **别买 ESP32-S3 之类「AI 模块」做本体**——跑不动 SenseVoice，
   最后你会把它降级成「点亮一个 LED」然后吃灰
2. **「能动」是另一个项目**——轮子/腿意味着电池、电机控制、避障，
   复杂度是这个语音项目的十倍。哪天真想做，单独开项目，别塞进这个仓库。
   本体上唯一值得加的「动」是点头舵机（SG90，纯装饰输出，40~70 元）

### 5.6 替代路线：旧安卓手机整机（了解即可，不做主线）

一部旧安卓手机可以身兼麦克风 + 喇叭 + 屏幕 + 算力（sherpa-onnx 有 Android 版）。
听起来很省，但安卓对后台常驻麦克风的限制极狠（杀后台、省电策略、各厂魔改 ROM 行为不一），
你会花 80% 的时间跟系统斗智而不是做机器人。等 N100 版稳定后当玩具可以，当主线不值。

**眼睛**：意图路由照 v2（听到「看看 / 这是谁 / 写的什么」才开摄像头，平时不开）。

**兜底**：
- N100 实测跑不动 → 留在笔记本常驻，「实体化」降级为笔记本 + 支架，不影响任何功能
- InsightFace 装不上 → 眼睛只做 RapidOCR 读字，认人砍掉
- **最后退路**：S6 整个不做（v2 原话：可以永远不买、永远不做）

## 8. 兜底总表（一页看全）

每一层都先想好退路再动手。原则：**退路永远是「回到现状」，现状永远完整可用。**

| 层 | 首选 | 兜底 | 最后退路（= 现状） |
|---|---|---|---|
| 大脑 | DeepSeek API | 换任何 OpenAI 兼容端点（Qwen / GLM / Kimi，改 `base_url` 即可） | `--text` 键盘模式调试不依赖 API |
| 语音合成 | 本地 sherpa-onnx | edge-tts（已实现自动降级） | `--text` 模式不出声 |
| 记忆 4a | 启动读回历史 | 只读最近 N 轮 | 仅本次会话记忆 |
| 记忆 4b | 模型抽事实 + 去重 | 抽取失败跳过本轮 | facts 为空，无影响 |
| 记忆 4c | fastembed + numpy 余弦 | onnxruntime 手动加载 bge | 「最近 N 条 facts」占位 |
| VAD | silero-vad | 噪声底自适应 + 能量检测 | 固定阈值 0.015 手调 |
| 唤醒 | sherpa-onnx KWS | 调阈值 2.0～4.0 / 换更长唤醒词 | 按键触发（`--text`） |
| 脸 | Live2D + 旧手机 | 静态图 + CSS 动画 | 无脸，纯语音 |
| 打断 | 触屏打断 | 无打断（说完为止） | 同左 |
| 眼睛 | RapidOCR + InsightFace | 只做 OCR 读字 | 无眼睛 |
| 硬件 | 笔记本 | +USB 麦/音箱（期 B，60～140 元） | 全自带设备（期 A，0 元） |
| 本体 | N100（期 D，550～900 元） | 笔记本常驻 + 进程守护 | 需要时才开机 |
| 记忆数据 | 启动时备份 `xiaoyu.db.bak` | 手动拷贝 `data/` 目录 | 重建（对话可丢，facts 让模型重新总结） |
| 热情 | 每步都是能跑的成品 | 停在任何台阶 | S6 可永远不做 |
