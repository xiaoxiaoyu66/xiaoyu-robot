## 第 3 步 · 刷固件（20 分钟）

### 为什么这一步排在接线前面

刷机要反复插拔 USB、还可能按住 BOOT 进下载模式。**那会儿板子上什么都还没接，
少一半能弄坏的东西。** §4 本来就不需要接模块。

固件和工具**都已经下好了**，不用联网：

```
.scratch\firmware\v2.5.0_bread-compact-wifi-lcd.zip  →  解压出 merged-binary.bin
.scratch\firmware\tools\flash_download_tool.zip       →  解压出烧录工具
```

### 步骤

1. 打开解压出来的 `flash_download_tool_*.exe`
2. 弹窗选：**ChipType = ESP32-S3**，**WorkMode = Develop**，OK
3. 第一行那个 `...` 按钮 → 选 `merged-binary.bin`
4. **烧写地址填 `0x0`**（不是 0x1000 —— 这是合并了引导+分区表+固件的整包）
5. 右下角选板子的 **COM 口**，波特率 **921600**
6. 先点 **ERASE**（等它跑完），再点 **START**
7. 等 1~2 分钟，出现绿色的 `FINISH`

**成功**：绿色 `FINISH`。

**截图给我看**：出现 `FINISH` 的那个界面。

**卡住怎么办**：

| 现象 | 怎么办 |
|---|---|
| 一直「等待上电同步」/ 连不上 | **按住板子上的 BOOT 键不放 → 插 USB → 再点 START**（进下载模式） |
| 中途报错 | 波特率降到 **115200** 重试 |
| 换了根线还是不行 | 换一根确定能传数据的线 |

## 第 4 步 · 断电接线（40 分钟）⚠️ 唯一能烧板子的一步

**先拔掉 USB。** I2S / SPI 都不支持带电插拔。

> ⚠️ **动手之前先读 [`到货当天_手把手.md`](到货当天_手把手.md) §2.0.2** ——
> 那一节是"接反会烧"的三条（屏的丝印顺序、GPIO 33~37 不能用、麦克风只能 3.3V），
> 花两分钟看完再插线。

按三张表接（完整表在 [`到货当天_手把手.md`](到货当天_手把手.md) §2，
2026-09-23 已拿真硬件照片 + 上游 v2.5.0 原文逐条核过）：

- **麦克风 INMP441**：WS→4、SCK→5、SD→6、L/R→**GND**、VDD→**3V3**、GND→GND
- **功放 MAX98357A**：BCLK→15、LRC→16、DIN→7、**SD→3V3**、GAIN→悬空、
  VIN→5V/3V3、GND→GND；喇叭接绿色螺丝端子
- **彩屏 ST7789**：CS→41、RST→45、DC→40、SDA→47、SCL→21、BLK→42、
  VCC→3V3、GND→GND

**三条铁律再念一遍**：

1. **接线必须断电**
2. **所有模块共地**（每个模块的 GND 都接板子的 GND）
3. **只有 INMP441 的 VDD 是绝对 3.3V** —— 接 5V 会烧麦

**成功**：`手把手 §2.5` 那 5 条复查全打勾（逐根对 GPIO 编号 / 没有该接 3V3 却接了 5V /
3V3 和 GND 没短路 / 喇叭两根线没短路 / 都插紧了）。

**截图给我看**：**面包板俯视照片一张**，角度要能同时看清每根线的两头
（板子端 + 模块端）。一张拍不清就分两张：左半 / 右半。

**开工前先确认三件事（缺一样就先停下问我，别猜）**：

1. **功放那 7 根针的顺序** —— 正面只有型号没引脚名，**拍一张背面照**给我。
   这块板最常见的两种排法是互为倒序的，猜错会把 Vin 接到别的脚上。
2. **喇叭接哪** —— 那两颗圆的、中间有十字槽的金属是**螺丝端子**（拧紧就行）；
   要是两个扁的镀锡圆孔，那是**焊盘，得焊**。拍张近照。
3. **杜邦线的头** —— 一端是针、一端是洞（公对母），还是两头都是洞（母对母）？
   线头拍张近照。**这决定你怎么接**：两头都是洞就直接板子针 → 模块针；
   一头针一头洞就要拿面包板当接线排（针插进面包板孔、洞套在模块的针上）。

**自己要做的最后一道检查**：**拿这张照片跟上面三张表逐根对一遍 GPIO 编号。**
面包板上孔挨着，错一位是最常见的事，而且症状是"完全没反应"，最难猜。

**窗口 1**：

```powershell
cd "D:\JavaAI\XiaoYu Robot"

```

```

小智服务就绪 | 设备配网页里填 http://<本机IP>:8766 ｜ OTA 路径 /xiaozhi/ota/ | WebSocket 走 8767 口 /xiaozhi/v1/
```

## 第 8 步 · 把设备指到我们这儿（10 分钟）⚠️ 第一次连最容易卡在这里

配网页面里**有「服务端地址 / OTA 地址」这一栏**（固件里 `wifi_board.cc` 的
`config.show_ota_config = true` 就是这个开关）。把默认那串
`https://api.tenclass.net/xiaozhi/ota/` 改成：

```
http://<这台电脑的局域网IP>:8766/xiaozhi/ota/
```

### 三个坑，按这个顺序排

1. **别填 `127.0.0.1`** —— 那是"设备自己"，不是这台电脑。要填 `ipconfig` 里那个
   `192.168.x.x` / `10.x.x.x`。

2. **Windows 防火墙** —— 第一次连**大概率死在这儿**。
   跑 `--xiaozhi-only` 的时候它会弹一个"允许 Python 访问网络"的框，
   **一定要勾上「专用网络」再点允许**。
   要是当时点了「取消」或者没看见：控制面板 → Windows Defender 防火墙 →
   允许应用通过防火墙 → 找到 Python → 勾上**专用网络**。
   （症状：设备连不上，我这边**一条日志都没有**。）

3. **电脑和板子必须在同一个 WiFi / 同一个网段。** 板子连的是你在配网页面填的那个 WiFi，
   电脑也要在同一个上（手机热点 + 电脑连同一个也行）。

### 成功长这样（**我们窗口**里的日志）

```
小智：OTA 请求 | 设备=xx:xx:xx:xx:xx:xx | 板子自述={"board": "bread-compact-wifi-lcd", ...} | 已下发 {"websocket":{"url":"ws://192.168.x.x:8767/xiaozhi/v1/","token":"xiaoyu","version":1}}
小智：有人连上了 WebSocket，等它的 hello
小智：设备连上了 | 协议版本=1 | 传输=websocket | 音频=16000Hz/60ms/1ch | features=mcp
```

**这三行各说明什么**：

- 第 1 行 = **OTA 打通了**（设备来敲我们了，还把它自己是什么板子报上来了）
- 第 3 行 = **设备认了我们的协议**，音频参数也报上来了。
  `16000Hz/60ms/1ch` 跟固件里写死的一致 —— 对不上就该怀疑了。

**截图给我看**：配网页面那一栏（**要能看见你填进去的地址**）+ 我们窗口这三行日志。

### 失败怎么读

| 现象 | 结论 / 下一步 |
|---|---|
| 我这边一条日志都没有 | 地址填错 / 防火墙拦了 / 不在同一网段 → 回到上面三个坑 |
| 设备串口日志里 `Remote end closed connection without response` | **端口写错了**（比如把 8767 填进了 OTA 栏）。OTA 一定是 **8766** |
| 设备卡在"激活"界面不动 | 我们的 OTA 应答里混进了 `activation` 段 —— 那是**我们的 bug**，截图给我 |
| 设备还是在跟小智云说话 | 地址没改成功，它还在连默认的 `api.tenclass.net` |

## 第 9 步 · 跟我们自己的大脑说话（20 分钟）

> **也要赶在 23:30 之前** —— 语音识别和合成都在本机，但"答一句"要调 DeepSeek，那个要外网。

确认第 8 步已经连上了，然后：

1. 对着板子说一句一两秒的话，比如"小柚子，今天天气怎么样"
2. **等一会儿**。现在是一轮 ASR→LLM→TTS **全跑完才开始下发**，2~4 秒很正常，
   别以为它坏了就重复喊。
3. 它用**我们的声音**答你。

**怎么区分「小智云的声音」和「我们的声音」**：

- 最硬的判据：**它会不会用我们的记忆回答**。问它"我叫什么" —— 答对了就一定是这一套。
- 听感：小智云一直很热情、语速快；我们的是本机合成、音色是 `config.toml` 里选的那个。

**成功长这样**（我们窗口的日志）：

```
小智：这一轮答完 | 上行 1.4 秒音频 -> 2 段、共 3.1 秒回话 | 用时 2.8 秒
小智会话 xxx 已收工（对端断开）—— 发出 42 帧（音频 41 帧），忽略 0 个事件
```

## 卡住的时候，先分清是哪一半（速查表）

| 卡在哪 | 说明是什么问题 | 先看哪 |
|---|---|---|
| 没 COM 口 | 驱动 / 线 / 板子 | 第 2 步的驱动表；换个口、换根线 |
| 刷不进 | 没进下载模式 / 波特率 | 按住 BOOT 插 USB；降到 115200 |
| **第 5 步就烫** | **接线错**（最严重） | **立刻拔掉**，回第 4 步复查 |
| 第 6 步喊不动 | **硬件**（麦 / 功放 / 接线） | 串口日志 + 第 6 步症状表 |
| 第 8 步我这边没日志 | **网络**（地址 / 防火墙 / 网段） | 第 8 步那三个坑，按顺序排 |
| 第 8 步设备说 `Remote end closed` | **端口写错** | OTA 是 **8766** |
| 第 9 步日志里写明卡在识别/合成 | **我们的代码** | 截图给我 |
