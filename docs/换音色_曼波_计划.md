## 1. 好消息：接口早就留好了

`xiaoyu/tts/engine.py` 开头的原话：

> 接口故意做得很小，就一个方法：`engine.synthesize("你好") -> Speech(samples, samplerate)`。
> 这样以后想换 Kokoro、GPT-SoVITS，只要再写一个类，别的代码一行都不用动。

唯一接线点是 `build_engine()`（`engine.py:376`）。换音色 = **加一个类 + 加一处分支**，
对话逻辑、记忆、情绪、表情一行都不用动。

现在的两个引擎：

- `local`（默认）：sherpa-onnx + `vits-piper-zh_CN-huayan-medium`。零点几秒出音，音色普通
- `edge`：微软晓晓。好听，但每句话都要连一次微软（实测首块音频 0.88~11.76 秒）

**「曼波」这种社区音色，sherpa 的音色库里不会有** —— 它里面全是播音腔。

## 2. 三条路

| 路线 | 怎么做 | 什么时候选 |
|---|---|---|
| **A · GPT-SoVITS（推荐）** | 加载社区音色模型，本地推理 | 找得到现成模型 |
| **B · RVC 变声** | 现有 TTS 出音 → 变声成曼波 | 只有音频没有模型，或原声太脏 |
| C · 云端商业音色 | 火山 / 字节那类 | 只要快，不在乎联网和钱 |

GPT-SoVITS 自己又分两种用法，**成本差一个量级**：

- **零样本**：给 5~10 秒参考音频 + 它的文字，直接就能模仿。**不用训练**
- **微调**：要 1 分钟以上干净音频，训一次几十分钟。更像，但要求高

## 3. 这段录音的体检（实测 2026-09-20）

`data/20260920_185259.m4a`：17.13 秒 / 48kHz 立体声 / AAC 128kbps。

| 指标 | 实测 | 说明 |
|---|---|---|
| 能量分布 | 1000-3000Hz 占 59.5% | 很亮 |
| 低频 | 300Hz 以下只有 1.2% | 没有伴奏的低音 |
| 高频 | 6000Hz 以上只有 0.3% | **高频被削掉了** |
| 底噪 | 0.0025，开头 0.5 秒干净静音 | 安静，好 |
| 过零率 | 0.223（说话通常 0.02~0.15） | 偏高 |
| 自相关次峰 | 0.559（乐音 >0.3 就算高） | **很"有调"** |
| 我们自己的识别模型 | 整段只出「动」；3 秒窗口是「啊 / 嗯 / 我你 / 动的奇皮 / 啦 / 好点快的」 | **读不出内容** |

结论三条：

1. 是个很亮、很有调的声音，偏高音或者带旋律，**不是普通朗读**
2. 高频被削掉 + 识别读不出 → 很像**用外放录回来的**（扬声器 → 麦克风）。
   拿这个去训练，出来会闷
3. 这 17 秒**够做零样本参考，不够做微调**

## 5. 动手顺序

1. 查有没有现成音色模型（魔搭 ModelScope / HuggingFace / B站整合包）——
   有就跳到第 4 步，**省掉整条训练链**
2. 没有 → 准备数据：转 16k 单声道、切掉静音、**人工核对参考文本**
3. 装 GPT-SoVITS，先用零样本跑通「参考音频 + 文字 → 合成一句」
4. 写 `xiaoyu/tts/gptsovits.py` 的 `GptSoVitsEngine`，实现 `synthesize(text) -> Speech`
5. 接进 `build_engine()`，配置项加进 `TtsConfig`，
   **默认仍保持现在的本地引擎** —— 没装 GPT-SoVITS 的人不能因此跑不起来
6. 跑测试（`unittest` 与 `pytest` 数字必须一致）→ commit → push

## 6. 提前记着的坑

- **冷启动**：GPT-SoVITS 首次加载模型要几秒到几十秒，必须先 `warmup()`，
  否则第一句话就卡在那里。`SherpaEngine.warmup()` 就是这个套路
- **速度要先量**：有 GPU 才有意义。纯 CPU 上 RTF 可能 >1（生成比音频本身还慢），
  而现在 sherpa 是零点几秒。**动手前先测 RTF，不达标就别换**
- **合规**：如果是真人（尤其名人）的声音，自己玩没事，公开分发 / 商用要谨慎
- **别把音频提进 git**：`data/*` 已经被忽略，保持这样
