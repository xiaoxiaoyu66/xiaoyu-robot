## 0. 它是什么（硬事实，2026-09-19 复核）

| 项 | 值 |
|---|---|
| 仓库 | `78/xiaozhi-esp32`（MIT） |
| 体量 | **30,055 stars** / 6,995 forks，最后推送 2026-09-15（很活跃） |
| 变体 | 138 个板卡目录、**171 个固件发布变体**（含面包板 DIY 的 `bread-compact-*`） |
| 编译 | 需 ESP-IDF ≥ 6.0.1；**但我们用预编译固件，不用装工具链** |
| 芯片 | ESP32 / C3 / C5 / C6 / S3 / P4（**自定义唤醒词只支持 S3/P4**） |
| 传输 | WebSocket（`docs/websocket_zh.md`）、MQTT+UDP（`docs/mqtt-udp_zh.md`） |
| 音频 | Opus 流；传统「ASR+LLM+TTS」或 Realtime 端到端模型；有 AEC 的硬件可全双工 |
| 其它 | ESP-SR 离线唤醒（可自定义词）、声纹识别（3D-Speaker）、屏上表情、设备端/云端 MCP、38 语言 |

**一句话定位**：**它给"身体 + 协议"，我们做"大脑 + 性格"。** 互补，不是竞品 ——
所以"取长补短"在它身上是 4 件具体事，**不需要抄任何代码**。

## 1. 我们已经用了它哪三处（不是"待研究"，是"在用"）

1. **固件**：A 档板子刷的就是它的 `v2.5.0_bread-compact-wifi-lcd`（预编译产物）
2. **引脚**：我们的接线表来自它的 `main/boards/bread-compact-wifi-lcd/config.h`
   （麦 WS/SCK/DIN = 4/5/6、功放 BCLK/LRC/DIN = 15/16/7、
   屏 CS/RST/DC/MOSI/CLK/BLK = 41/45/40/47/21/42）
3. **硬指标**：开发板必须 **N16R8**，来自它的 `sdkconfig.defaults`
   （`FLASHSIZE_16MB` + `SPIRAM_MODE_OCT`）

## 2. ✅ 该做什么（4 件，每件都有验收动作）

### 2.1 先让硬件跑起来（**不碰我们的代码**）
刷固件 → 配网 → 喊「你好小智」能对话。
**验收**：它用自己的官方云能应答（这一步只验硬件，与我们的 Python 无关）。
流程见 [`A档到货开工.md`](A档到货开工.md) §5-§6。**这一步没过，别往下走。**

### 2.2 写「小智设备协议」的服务端 —— **这才是 A 档的核心任务**
设备发 `hello`(JSON) + Opus 音频帧；我们回 `hello`，再用**我们自己的**
LLM / 记忆 / 性格 / TTS 回应。
- 协议文档：小智仓库 `docs/websocket_zh.md`（本机用 `Invoke-WebRequest` 下）
- 放置：新建 `xiaoyu/xiaozhi/`
- **验收**：**喊「小柚子」→ 它用我们的记忆和性格回答 → 说到一半能打断**

### 2.3 把唤醒词换成「小柚子」
S3 支持 MultiNet 自定义唤醒词（拼音输入），我们 PC 端 KWS 现在用的词就是「小柚子」
（`config/keywords.txt`）。
**验收**：设备端喊「小柚子」能醒，和 PC 端词一致。

### 2.4 把表情换成我们自己的
官方 assets 生成器（`78/xiaozhi-assets-generator`）**纯浏览器本地生成 `assets.bin`**，
一次打包表情包 + 唤醒词 + 字体 + 背景。
它的表情位是 21 个，**我们的 5 个情绪（`happy / sad / angry / surprised / neutral`，
见 `xiaoyu/llm/emotion.py` 的 `VALID_MOODS`）正好是它的子集**，映射表是白给的。
**验收**：设备屏上出现的是**我们的设计**，不是它的 Twemoji 表情包。

## 3. ❌ 不该做什么（决策边界，每条都论证过，别重开讨论）

| 不做 | 为什么 |
|---|---|
| **不写、不改 C++ 固件** | 用预编译产物。改固件等于把"我们的知识"绑死在别人的代码上 |
| **不把它的云（xiaozhi.me）当默认** | 那就成了"别人的机器人"：记忆、性格都在别人那 |
| **第一版不用 Realtime 端到端语音模型** | 它省事，但会把 LLM 那一层整个交出去，我们的记忆三层 / 情绪 / 性格就没地方插。**是"以后想偷懒"的备选，不是现在** |
| **第一版不上 MQTT + UDP** | 先 WebSocket：够用、好调、文档全。多一种传输就多一处会坏 |
| **不换掉我们的大脑** | 记忆三层 / 情绪 / 性格 / 误唤醒统计 / 常驻自愈是护城河（见 §5），对方的记忆是"配置化接外部服务"（mem0 / RAGFlow），比我们更依赖环境 |
| **不抄它的 Vue 管理台、不引 Java 后端** | 我们用不上，进来只会增加维护面 |
| **不改引脚** | 引脚在固件里写死。硬件装反只允许走**配置项**（例如 `XIAOYU_BODY_INVERT_PAN`），**不许在代码里到处反符号** —— S6a 那次返工的根因就是这个 |
| **不在没跑测试的情况下动现有语音链路** | 新代码先写纯逻辑 + 单测，最后**用一个开关**接进 `app.py`，默认关 |

## 5. 我们比它强的（护城河，**别在"取长补短"里被顺手换掉**）

- **记忆三层**：SQLite 存对话 + 定期摘要 + fastembed 向量检索（4c），**全本地、不依赖外部服务**
  （`xiaoyu/memory/`）
- **情绪系统**：`[emotion]` 标记的剥离与解析，含"标记漏进正文"和"回调接错签名"两个已修坑
  （`xiaoyu/llm/emotion.py`、`tests/test_emotion_wiring.py`）
- **性格**：`config/persona.md` + 示例
- **误唤醒有数**：`--wake-report` 按天统计、凌晨 0~6 点单独拎出来（`xiaoyu/app.py`）
- **常驻自愈**：守护进程 + 开机自启 + 崩溃判定只写一份（`xiaoyu/lifecycle.py`、
  `scripts/guardian.py`、`scripts/install_autostart.py`）
- **身体接口层**：`xiaoyu/body/`（`ServoBackend` 接口 + 假舵机 + `gaze → 转头角度`，默认关）
  —— 真舵机买回来**只换 backend**，不动对话逻辑

## 6. 动手顺序（照这个抄）

1. 读 [`A档到货开工.md`](A档到货开工.md) §1（环境事实）与 §5-§6（刷机、验硬件），
   **先把硬件跑通，这一阶段不碰仓库代码**
2. 下 `docs/websocket_zh.md` 读协议（`Invoke-WebRequest`）
3. 新建 `xiaoyu/xiaozhi/`：**先只写协议解析 + 单测**（不联网、不接硬件也能测）
4. 再单独一步加 Opus 编解码依赖，加完立刻写最小单测
5. 写一个最小服务端：设备连上来、回声/固定语，先证明"能连上、能收发"
6. 才接我们的 LLM / 记忆 / TTS → 端到端跑通 → 能打断
7. 最后用**一个开关**接进 `app.py`（默认关，老链路一行不受影响）
8. **每一步都**：跑 309 测试 → commit → push → 把进度写回 `HANDOFF.md` 和 `TODO.md`
