## 1. 最容易被漏掉的成本：N100 什么都没带

笔记本有麦克风、喇叭、摄像头、屏幕 —— **这四样都是白送的**，
而 N100 小主机一样都没有。搬过去要一样一样补上。

| 笔记本白送的 | N100 有吗 | 怎么办 | 预算（估算） |
|---|---|---|---|
| 麦克风 | ❌ 没有 | USB 麦克风（或带麦的 USB 音箱） | 50~200 |
| 喇叭 | 多半只有一个 3.5mm 口 | 3.5mm 小音箱，**音量固定** | 50~100 |
| 屏幕（脸） | ❌ 没有 | 平板当脸 —— 就是阶段 B 要做的事 | 0（pad 已有） |
| 摄像头（眼睛跟随） | ❌ 没有 | USB 摄像头；**不买也行**，关掉眼睛跟随，其它功能一点不受影响 | 50~150 |
| 算力 | ✅ N100 够（见 §5.1 算力账本） | — | — |

**主机 + 配件合计大约 800~1500 元**（主机 550~900 + 上面几样 + 支架外壳）。
这笔钱要花在阶段 C 之前，不是现在。

> 别一次买齐。**先买主机，到手先验证跑不跑得动（M2），不行就退，损失为零。**

## 2. A · 笔记本跑满一周（进行中，0 元）

**做什么**：什么都不做，让进程连续跑七天不重启。

**第一次开跑为什么失败（2026-09-18 查，已修）**：
原方案是「计划任务 → `scripts\run_forever.cmd`（守护循环）」。任务 XML 里埋着四个坑，
任何一个都足以把「跑一周」变成「跑一天」：

| 坑 | 默认值 | 后果 |
|---|---|---|
| `DisallowStartIfOnBatteries` | `true` | 拔一下电源线，任务当场被停 |
| `StopIfGoingOnBatteries` | `true` | 切到电池就杀 |
| `ExecutionTimeLimit` | `PT72H` | 第 4 天系统亲手把任务掐掉 |
| 启动的是 `.cmd` | —— | **必然弹一个黑窗口；顺手一关，守护和本体一起死** |

最后一个正是当天的真实死法：窗口被关掉之后，`logs\guardian.log` 里只有一条
`guardian: starting`，**再没有任何 `exited` 行** —— 进程不是崩的，是被连根拔的。

**已改成**：任务直接启动 `pythonw.exe scripts\guardian.py`。
`pythonw.exe` 起的进程天生没有控制台窗口，关无可关；另外三个开关在
`scripts\install_autostart.py` 里写死成关掉。原 `run_forever.cmd` 已删（活全被 `guardian.py` 接走）。

**起跑时间：2026-09-18 20:21:42**（重启后自启的那一刻 —— 计时从这里算）

三个坑都做了真机验证，不是"应该没问题"：

| 坑 | 怎么验的 | 结果 |
|---|---|---|
| 窗口能被关掉 | `MainWindowHandle`：守护和本体两个进程都是 `0` | 没有窗口，关无可关 |
| 拔电源被杀 | Kernel-Power 事件 105：20:16:37 拔电、20:19:48 插回；期间 20:18:41 查 pid | pid `28748` **没变**，uptime 连续 —— 切到电池不杀进程 |
| 重启不自己起来 | 20:21:26 开机 → 20:21:41 守护起来 → 20:21:42 本体起来 | 登录后 **15 秒**自动拉起，全程无人手动干预 |
| 断网就崩 | 用户手动断网实测 | 通过 —— 恢复后没退出（用户 2026-09-18 实测） |
| 半夜被 Windows 更新重启 | 用户确认这台机器**没有**自动更新 | 不适用 —— 下面「使用时段」那步手点提醒可以划掉 |

`logs\guardian.log` 到目前两条 `starting`（手动起跑一次 + 重启自启一次）、
**0 条 `exited`** —— 与预期完全一致。旧的 `.cmd` 时期混合编码日志已归档为
`guardian_cmd-era_20260918.log`，不再往新日志里掺 GBK。

**随时查活着没**：

```
py -3.11 scripts\install_autostart.py --status
```

**验收**：
- `--status` 里**「本体中途崩溃次数」应该是 0**；有一次 `exited` = 本体崩过一次，
  去查 `logs\error.log` 和 `logs\xiaoyu_*.log`。
  （注意：「守护启动次数」**不是**异常信号 —— 每次开机 / 重登录都会 +1。）
- `--status` 的「已连续运行」应该是 7 天上下，而不是几小时。
- `python -m xiaoyu --wake-report`：凌晨 0~6 点那一列接近 0（半夜没有自己醒）。
- 误唤醒次数在可接受范围（没有客观阈值，看体感）。

**退路**：一周内崩了不算失败 —— 崩了才有日志可查，这正是跑这一周的目的。

### 2.1 一定要跑满一周吗？

先把「这一周到底能买到什么」拆开看：

| 想验的东西 | 真需要 7 天吗 | 更划算的做法 |
|---|---|---|
| 内存 / 线程 / 连接泄漏 | **不需要** | 浸泡测试：把一周的对话量压进 1~2 小时，每小时记一次 RSS，半天就有斜率 |
| 偶发崩溃、状态机卡死 | **不需要**，但需要"轮数"不是"天数" | 同上。自然跑一周绝大部分时间是空闲的，轮数远不如压测 |
| 误唤醒（尤其凌晨） | **需要**，但 1~2 个通宵就够看量级 | 跑 2 晚，看 `--wake-report` 的 0~6 点那一列 |
| 系统的半夜行为（扫描 / 备份 / 休眠） | **需要** 1 个完整的凌晨 | 1 晚 |
| 你家环境的周波动（WiFi、电源、你不在家） | 需要 | 唯一真正只能靠时间的东西，风险也最低 |

结论：7 天里真正**不可压缩**的只有「凌晨的静默」和「环境的周波动」；
前者 1~2 晚就够，后者风险很低。剩下的都能用压测换时间。

所以两条路，按工期挑：

- **原版（7 天）** —— 成本其实接近 0：你什么都不用做，它在那儿跑着。
  唯一代价是「这周先不开下一件事」。不急就走这条，证据最完整。
- **压缩版（2~3 天）** —— 1 次浸泡测试 + 2 个通宵，然后对账收工。
  证据强度不比原版差（因为主动打了边界），缺的只是「周尺度漂移」。

一句话：**一周不是因为它值一周，是因为它免费。** 等得起就走原版；
想早点开工，压缩版够用，别为仪式感多等四天。

## 3. B · 脸搬去平板（下一步，0 元，1 次开工）

**为什么排在 N100 前面**：脸是唯一还需要一块屏的东西。先把消费端打磨好，
主机搬家时就不用再动它；而且它有当天的可见收益，不依赖任何采购。

**开工前必须知道的两件事（2026-09-18 查证）**：

1. **脸页面现在没法在平板上打开。** `xiaoyu/face/server.py` 只起了 WebSocket
   （`websockets.serve`），**不伺服 `face/index.html`**。笔记本上是直接双击本地文件打开的，
   平板做不到。→ 得让主控把这张网页也用 HTTP 发出去（很小的一件事）。
2. **脸页面一变成 HTTP + 局域网 IP，平板的常亮就没了。**
   `navigator.wakeLock` 要求**安全上下文**（https 或 localhost），
   `http://192.168.x.x` 不算 —— 页面里那段 Wake Lock 代码在平板上会直接跳过，屏幕会自己熄。
   → 两条路：**(a) 平板系统设置里把息屏改成"永不"**（简单，推荐）；
   **(b) 用 Fully Kiosk Browser 这类自带 keep-screen-on 的浏览器**。

**做什么**：
1. 主控顺带伺服 `face/index.html`（浏览器打开 `http://<主机IP>:8765/` 就是脸）。
   这样页面里的 `location.hostname` 天然就是主机地址，**配对变成零操作**，不用输 IP。
2. 平板上打开、加书签/主屏幕、全屏。
3. 平板系统音量**关到 0** —— 半双工铁律：脸的喇叭不许出声，出声会喂回麦克风。
4. 平板息屏改成"永不"（或换 kiosk 浏览器）。
5. 支架固定（脸要立着或斜靠，别平躺 —— 平躺人看不到）。

**验收**：把笔记本合盖放到一边，喊唤醒词 —— 平板上的脸有反应、说话对口型、
情绪变表情；**挂一整天不断线**（断线自动重连已有，这条是验它真的会重连）。

**退路**：平板太老、浏览器不支持 WebSocket/Canvas → 脸退回笔记本，其它一概不受影响。
这条线本来就是可选的。

## 4. C · 主机搬去 N100（要花钱，2~3 次开工）

### 4.1 M2 · 到手先验证，别急着迁（1 次开工）

**只做一件事**：装上 venv 和依赖，跑

    python scripts\bench_latency.py --no-llm

ASR / TTS 耗时可接受（预期 TTS <0.5 秒、ASR <0.5 秒）**再动手迁移**。
不行就退货，损失为零。**这一步的产出是把 §5.1 表格里的"推算"换成"实测"。**

### 4.2 M3 · 迁移（1~2 次开工）

按顺序：

1. **先定操作系统**（见 §6，这是搬之前最大的一个选择）。
2. 依赖装进 venv，`pip freeze > requirements.lock` **锁死版本**
   —— 现在的 `requirements.txt` 全是 `>=`，在 N100 上复现不出同样的环境。
3. 拷代码 + `data/xiaoyu.db`（它的记忆跟着走）。
4. **重新下载全部模型**（约 250MB，走 GitHub 1.28MB/s 那个老坑，预留一小时）。
5. 重新查音频设备名字，改 `.env`：
   现在是 Windows 的叫法（`XIAOYU_SPK_DEVICE_NAME=扬声器` / `XIAOYU_MIC_DEVICE_NAME=麦克风`），
   换系统后名字完全不同。**机制不用改** —— `xiaoyu/audio/devices.py` 的"按名字匹配"两边都成立。
6. 改成开机自启：Windows 沿用 `scripts\guardian.py`（`install_autostart.py` 注册的任务）；
   Linux 不用它，systemd 的 `Restart=always` 直接顶掉这层。
7. `python -m xiaoyu --check` 全绿 → 不接显示器键盘跑一天。

### 4.3 眼睛跟想要单独确认

`XIAOYU_VISION_CAMERA=0` 指的是**第 0 号**摄像头。N100 上插 USB 摄像头后，
编号可能不是 0，要重新试。**不买摄像头就把眼睛跟随关掉**，其余功能不受影响。

**验收**：不接显示器、不接键盘，插电就自己起来；喊醒能聊；手机上能看到脸。
行为和笔记本一致 —— "一致"是硬标准，不许出现"N100 上偶尔不灵"。

**退路**：N100 实测跑不动 → 留在笔记本常驻，"实体化"降级成笔记本 + 支架，
**一个功能都不少**。这也是为什么 A 阶段必须先跑扎实。

## 5. D / E · 壳子和随身

**D · 外壳（纯手工，不碰代码，1 次开工）**：亚克力/3D 打印支架、走线、散热。
唯一值得加的"动"是点头舵机（SG90，40~70 元，纯装饰输出）。

**E · 随身（远期，不排期 —— 用户明确说以后再做）**：
- **前置条件：桌面版先稳定跑满一个月**，把功耗、发热、实际续航量出来。
  现在设计电池等于瞎猜。
- 要额外加：电池（PD 诱骗器 + 45W 以上充电宝，整机 10~20W，20000mAh 大概撑 3.5~7 小时）、
  外壳、散热、（可选）屏幕。
- **必须联网**：N100 跑不动像样的中文大模型，随身形态得挂手机热点，断网时它只能听不能说。
- 下单前如果已经想着随身：**优先挑原生支持 USB-C PD 供电的型号**，以后省一个诱骗器。
- 另一条路（**不建议**）：ESP32 + 服务器，等于换一个项目，而且把延迟敏感的环节搬到远端，
  和 2026-09-17 刚做完的提速是反方向。

## 6. 决策点：Linux 还是 Windows（搬之前先定）

| | Linux（Debian/Ubuntu） | Windows |
|---|---|---|
| 资源 | 省，开机自启干净，不需要显示器 | 4 核要被系统吃掉不少 |
| 音频 | 要重踩 ALSA / PulseAudio 一套新坑 | 已踩平，**代码一行不用改** |
| 代码 | 要改一行（见下） | 不用改 |
| 用户熟悉度 | 新 | 熟 |

**已知的代码改动点（2026-09-18 全项目扫过一遍）**：

- **`xiaoyu/vision/tracker.py:105` 用了 `cv2.CAP_DSHOW`** —— 这是 Windows 专用的摄像头后端，
  Linux 上必须改（按平台选后端）。**这是全项目唯一一处平台绑定的代码**，
  之前记的"代码零改动"要修正成"改一行"。
- `scripts/guardian.py` 本身跨平台（只用 `subprocess` + `pathlib`），Windows 专用的只有
  `scripts/install_autostart.py`（计划任务那部分）；Linux 上换 systemd unit。
- `xiaoyu/text.py` 读文件时会依次试 `utf-8-sig → gbk → utf-16`，在 Linux 上无害（第一项就中）。
- 其余全跨平台：`pathlib` 走路径、没有 `platform.system()` 改行为、没有平台专用依赖。
