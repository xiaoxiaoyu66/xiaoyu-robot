## 1. 开箱（**先别接线**，30 分钟）

### 1.1 核对型号丝印

| 件 | 认什么 |
|---|---|
| ESP32-S3 板子 | 板子丝印/包装要有 **N16R8**（16MB Flash + 8MB **八线** PSRAM） |
| 麦克风 | **INMP441** |
| 功放 | **MAX98357A** |
| 彩屏 | **ST7789** · 240x320 |

> **N16R8 这条不能将就**：固件里写死了 16MB Flash + 八线 PSRAM，买成 N8R2 / N16R2
> 刷进去起不来。丝印对不上**立刻找商家换**，别先接线。

### 1.2 板子**单独**插电脑（什么都先不接）

用板子自己的 Type-C 口接到电脑。

- Windows 会「叮」一声，**设备管理器 → 端口(COM 和 LPT)** 里应该多出一个 COM 口
- 记住这个号（比如 `COM5`），后面刷机要用

### 1.3 没出现 COM 口 → 装 USB 串口驱动

看板子 USB 口旁边那颗**小芯片的丝印**，按型号装：

| 丝印 | 装什么 |
|---|---|
| `CH343` / `CH340` | CH34x 驱动（沁恒官网 / WCH） |
| `CP2102` / `CP210x` | Silicon Labs CP210x VCP 驱动 |

装完拔插一次再看。**这一步不过，后面全做不了。**

### 1.4 拍照留证

拼多多的单是**先用后付**——拆包时把每件的丝印拍一张，有问题好举证。

## 2. 接线

### 2.0 三条铁律

1. **接线必须断电** —— 拔掉 USB 再接。I2S / SPI 都不支持带电插拔。
2. **所有模块必须共地** —— 每个模块的 GND 都接到板子的 GND。只接一半会出现
   「喇叭有电流声但不出声」这种查半天的毛病。
3. **只有 INMP441 的 VDD 是绝对 3.3V** —— 接 5V 会烧麦。其余照表接。

面包板两侧那两条**长条孔**（红/蓝线）就是电源轨：一条全接 3V3，一条全接 GND。
先把这两条轨从板子引出来，后面每个模块就近取电，会省一半的线。

### 2.1 麦克风 INMP441

| 模块脚 | 接到板子 GPIO |
|---|---|
| WS | **4** |
| SCK（有的丝印写 BCLK） | **5** |
| SD（有的丝印写 DIN / DATA） | **6** |
| L/R | **GND**（选左声道） |
| VDD | **3V3 —— 只能 3.3V** |
| GND | GND |

板的【向下焊】是**插在面包板上**用的：排针插进面包板中间，
再从面包板两侧的排孔用杜邦线引到模块。

### 2.2 功放 MAX98357A + 喇叭

| 模块脚 | 接到板子 GPIO |
|---|---|
| BCLK | **15** |
| LRC（有的写 LRCLK / WS） | **16** |
| DIN | **7** |
| SD | **3V3**（常开；**不接会一直静音**） |
| GAIN | **悬空**（默认 9dB，够了） |
| VIN | 5V 或 3V3 都行 |
| GND | GND |
| 喇叭 | 接模块上那个**绿色螺丝端子**（+ / −），喇叭两根针插进去拧紧 |

> **最容易踩的两个**：`SD` 忘了接 3V3（表现是「一切正常但没声音」）、
> `BCLK/LRC/DIN` 三根接错顺序（表现是「有声音但是电流噪声/完全不对」）。

### 2.3 彩屏 ST7789（240x320）

| 屏脚 | 接到板子 GPIO |
|---|---|
| CS | **41** |
| RST（有的写 RES） | **45** |
| DC（有的写 RS） | **40** |
| SDA（有的写 MOSI） | **47** |
| SCL（有的写 CLK / SCK） | **21** |
| BLK（有的写 BL / LED） | **42** |
| VCC | 3V3 |
| GND | GND |

### 2.4 板子上不用自己接的

- **BOOT 键（GPIO0）**：刷机进下载模式用，板载
- **板载 LED（GPIO48）**：固件会自己点它

### 2.5 上电前的复查（**花 5 分钟，能救一块板子**）

- [ ] 逐根对一遍上表，尤其 **GPIO 编号**（面包板上孔挨着，很容易错一位）
- [ ] 有没有哪根线插到了板子的 **5V** 脚却应该接 3V3（INMP441 最怕这个）
- [ ] 3V3 和 GND **没有直接短在一起**（插电前目视检查一遍）
- [ ] 喇叭两根线没短路（拧端子时别让线头搭在一起）
- [ ] 模块都插紧、杜邦线插到底

插 USB，看两件事：

1. 设备管理器里 COM 口还在（说明没接短路）

## 4. 刷固件

### 4.1 解压

```
.scratch\firmware\v2.5.0_bread-compact-wifi-lcd.zip  →  解压出 merged-binary.bin（约 9.6MB）
.scratch\firmware\tools\flash_download_tool.zip       →  解压出烧录工具
```

### 4.2 Flash Download Tool 步骤

1. 打开解压出来的 `flash_download_tool_*.exe`
2. 弹窗里选：**ChipType = ESP32-S3**，**WorkMode = Develop**，OK
3. 第一行「文件」那个 `...` 按钮 → 选 `merged-binary.bin`
4. **烧写地址填 `0x0`**（不是 0x1000 —— 这是个合并了引导+分区表+固件的整包）
5. 右下角选板子的 **COM 口**，波特率 **921600**
6. 先点 **ERASE**（清空，等它跑完），再点 **START**
7. 等 1~2 分钟，出现绿色的 `FINISH` = 成功

### 4.3 烧不进去怎么办

| 现象 | 怎么办 |
|---|---|
| 一直 `等待上电同步` / 连不上 | **按住板子上的 BOOT 键不放 → 插 USB → 再点 START**，进下载模式 |
| 中途报错 | 波特率降到 **115200** 重试 |
| 换了根线还是不行 | 有些 Type-C 线**只有电、没有数据**，换一根 |

> ⚠️ 这一步走的是它**自己的云**（xiaozhi.me）。让它在这儿工作一会儿没关系，
> 但**我们的目标不是这个** —— 见下一节。

### 没声音 / 它不理我

按这个顺序查（**先看串口日志，别瞎猜**）：

```powershell
py -3.11 -m serial.tools.miniterm COM5 115200
```

（`COM5` 换成你的口；退出按 `Ctrl+]`）

| 症状 | 大概率是 |
|---|---|
| 完全不理我，日志也没反应 | INMP441 的 WS/SCK/DIN 接错，或 **VDD 没接** |
| 它答应了，但没声音 | MAX98357A 的 **SD 脚没接 3V3** |
| 有刺啦声但听不清 | 功放三根信号线顺序错 |
| 屏幕一直白屏 | 屏的 CS/DC/RST 接错（不影响语音，可以最后再修） |

## 6. ⚠️ 关键一步：让设备连**我们自己的**服务端

**这一步是 A 档真正的任务，也是最容易卡住的地方 —— 之前没写清楚，现在写清楚。**

### 6.1 先搞懂设备是怎么找服务器的

设备**不会**直接连一个写死的 WebSocket 地址。它的流程是：

```
设备开机
   ↓
读一个「服务端地址」→ 默认是固件里的 https://api.tenclass.net/xiaozhi/ota/
   ↓
向这个地址发一个 HTTP 请求（叫 OTA 检查）
   ↓
服务器回答里带一段： {"websocket": {"url": "ws://...", "token": "..."}}
   ↓
设备把 url / token 存进自己的闪存
   ↓
这才去连那个 WebSocket → 发 hello → 开始对话
```

**所以我们的服务器要开两个口子，而且是两个不同的端口：**

| 口子 | 干什么 | 例 |
|---|---|---|
| **HTTP**（8766） | 回答上面那个「服务端地址」请求 | `http://<我们电脑IP>:8766/xiaozhi/ota/` |
| **WebSocket**（8767） | 真正对话 | `ws://<我们电脑IP>:8767/xiaozhi/v1/` |

> ⚠️ **这一段原来写的是「这两件事可以同一个端口」，那是错的 —— 2026-09-22 实测推翻。**
>
> 脸页那套（`xiaoyu/face/server.py`）确实同口能跑，但那是**人拿浏览器点**的场景：
> 浏览器发的是 GET，没有 body。小智设备不一样 —— 上游 `ota.cc` 发的是 **POST + body**
> （它要把 `GetSystemInfoJson()` 报上来）。而 `websockets` 的 HTTP 层碰到带 body 的请求
> **直接关连接**：
>
> ```
> websockets/http11.py:  if int(headers["Content-Length"]) != 0:
>                            raise ValueError("unsupported request body")
> ```
>
> 症状是设备侧只留一句 `Remote end closed connection without response`，
> 而拿浏览器 GET 同一个地址却是 200 —— 这种"换个客户端就好"的毛病最费时间。
>
> 所以定成：**OTA 走标准库的 `ThreadingHTTPServer`**（收 POST 没问题），
> **WebSocket 走 `websockets`**，两个口。
>
> **设备连哪个口不是它自己决定的，是我们告诉它的**：OTA 应答里的 `websocket.url`
> 写的是哪个端口，它就连哪个。所以分成两个口对设备**毫无影响** ——
> 上游默认那套本来就是让它去连另一个域名的另一个端口。

### 6.2 我们服务器要回答的那段 JSON

```json
{
  "websocket": {
    "url": "ws://10.35.76.134:8767/xiaozhi/v1/",
    "token": "xiaoyu",
    "version": 1
  }
}
```

出处（上游源码，不是编的）：

- 设备会把返回里的 `websocket` 这个对象**逐个键**写进自己的闪存（`main/ota.cc`）
- 连接时读的是 `url` / `token` / `version` 三个键（`main/protocols/websocket_protocol.cc`）
- `token` 里**没有空格**的话，设备会自动补成 `Bearer <token>`，所以随便给个短串就行
- `version` 显式给 1，跟固件默认值一致（我们服务端也只支持 1）
- ⚠️ **`websocket` 段必须存在** —— 少了它设备会退回 MQTT，那就完全接不上了
- ⚠️ **绝不能有 `activation` 段** —— 里面有 `code` 或 `challenge` 的话，
  设备会**卡在激活界面不往下走**（上游源码钉死的两条，`ota.py` 的用例专门盯着）

### 6.3 怎么把设备指到我们这儿

配网页面里**有「服务端地址 / OTA 地址」这一栏**（固件里 `wifi_board.cc` 写着
`config.show_ota_config = true`，就是这个开关）。把默认那串
`https://api.tenclass.net/xiaozhi/ota/` 改成：

```
http://<这台电脑的局域网IP>:8766/xiaozhi/ota/
```

电脑 IP 用 `ipconfig` 查（本机是 `10.35.76.134`，可能变）。

**改完怎么知道成功了**：看我们自己服务器的日志 —— 设备开机时应该来一条
`POST /xiaozhi/ota/` 的请求。看到了就说明**打通了**。

> 如果配网页面上找不到这一栏：别猜，先把设备重启一次，在串口日志里看它实际去请求
> 了哪个地址（日志会打 `Check version` 那一段），再决定怎么改。**不改掉这个地址，
> 设备永远连不到我们** —— 这是必经的一步。

## 7. 装我们这边（Python）

### 7.1 依赖

```powershell
cd "D:\JavaAI\XiaoYu Robot"
py -3.11 -m pip install websockets pyserial av
```

`av` 就是 Opus 编解码：PyAV 自带 ffmpeg + libopus，约 27MB，装完就能用。

> ⚠️ **别去装 `opuslib` / `pyogg`** —— 2026-09-22 在这台机器上都试过了：
> `opuslib` 装得上但一运行就 `Exception: Could not find Opus library`（系统里没有 opus.dll），
> `pyogg` 里**根本没有裸编解码器**（只有 `OpusFile` / `OpusFileStream`，
> `AttributeError: module 'pyogg' has no attribute 'OpusEncoder'`）。
> **`av` 已经装好了**，这段是给重装系统留的记录。

装完**不用板子**就能验一次：

```powershell
py -3.11 scripts\xiaozhi_fake_device.py --selftest
```

看到 `编解码自检通过` 就成了。

### 7.2 端口别撞

**`8765` 已经被本体占着**（表情脸服务，同时跑 HTTP + WebSocket），而且在跑一周的
浸泡验收（**到 2026-09-23 16:41 截止，在那之前别重启本体**）。

小智这一层要**空出两个口**：

| 口 | 谁在用 |
|---|---|
| **8766** | OTA（HTTP） |
| **8767** | WebSocket（对话） |

两个都要空着 —— 被别的程序占了服务就**起不来**，日志里会明说是哪个口。
（为什么是两个口而不是一个：§6.1 那个「坑」。）

### 7.3 起服务

服务端**已经写好了**（2026-09-22）。开关默认是**关**的 —— 没板子的时候它不该占端口、
不该建编解码器。两种跑法：

```powershell
# A. 只跑板子这一条路 —— 不要麦克风 / 喇叭 / 摄像头。板子第一次连，推荐先跑这个
$env:XIAOYU_XIAOZHI_ENABLED='1'
py -3.11 -m xiaoyu --xiaozhi-only

# B. 完整本体（本机的麦 / 喇叭 / 唤醒词 / 摄像头都参与，再加上板子这条路）
$env:XIAOYU_XIAOZHI_ENABLED='1'
py -3.11 -m xiaoyu
```

为什么先跑 A：完整本体要先过麦克风、喇叭、唤醒词、摄像头四道门，任何一道不过就起不来，
**那时候你分不清是板子的问题还是本机的问题**。A 只有「板子收音 → ASR → 大脑 → TTS →
板子放音」这一段，变量最少。

起不来的话日志里会直说原因（端口被占 / 没装 PyAV）。**不用板子**也能验一遍：

```powershell
py -3.11 scripts\xiaozhi_fake_device.py            # 自己起服务 + 自己当设备，走完整轮
py -3.11 scripts\xiaozhi_fake_device.py --ota http://127.0.0.1:8766/xiaozhi/ota/   # 打正在跑的 A
```
