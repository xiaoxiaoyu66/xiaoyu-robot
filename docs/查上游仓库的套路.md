# 查上游仓库的套路（2026-09-19 整理，都是本机实测能跑的）

> 目的：想搞清楚一个开源项目**到底怎么用、能不能为我所用**时，用最短的路拿到
> **硬事实**（引脚、规格、协议、有没有现成固件），而不是看完一堆二手教程还在猜。
>
> 这套是查 `78/xiaozhi-esp32` 时踩出来的 —— 那次就是靠读它的 `config.h` 和
> `sdkconfig.defaults`，才在一个小时里定下了「必须买 N16R8」「屏必须是
> ST7789 240x320」「引脚是 4/5/6 + 15/16/7 + 41/45/40/47/21/42」这几件硬指标。

## 0. 本机的两个坑（先记住）

1. **`curl.exe` 到 GitHub 是被挡的**（返回 000），但 **PowerShell 的
   `Invoke-WebRequest` 正常**。所以下面全用 PowerShell。
2. **`github.com` 时通时不通**，但 `raw.githubusercontent.com` 和 `api.github.com`
   基本一直通。`git push` / `git clone` 一般没问题。

## 1. 四条命令（够用 90%）

```powershell
$ProgressPreference = 'SilentlyContinue'

# ① 列目录：看看仓库里有什么（最有用的第一眼）
(Invoke-WebRequest "https://api.github.com/repos/<owner>/<repo>/contents/<path>" -UseBasicParsing).Content |
  ConvertFrom-Json | Select-Object -ExpandProperty name

# ② 读单个文件（raw 最快，不解 JSON）
(Invoke-WebRequest "https://raw.githubusercontent.com/<owner>/<repo>/main/<path>" -UseBasicParsing).Content

# ③ 只想搜关键词，别把整篇文章糊到屏幕上
(Invoke-WebRequest "https://raw.githubusercontent.com/<owner>/<repo>/main/README.md" -UseBasicParsing).Content -split "`n" |
  Select-String -Pattern "PSRAM|Flash|引脚|GPIO"

# ④ 有没有现成的固件/发布包可以直接下（决定"要不要自己编译"）
(Invoke-WebRequest "https://api.github.com/repos/<owner>/<repo>/releases" -UseBasicParsing).Content |
  ConvertFrom-Json | ForEach-Object { $_.assets } | Where-Object { $_.name -match "关键词" } |
  Select-Object name, @{n='MB';e={[math]::Round($_.size/1MB,2)}}, browser_download_url
```

> 网页脚本工具（浏览器自动化）留给"必须登录 / 必须点页面"的站点。
> **读开源仓库根本用不着它**，多一层就多一处会坏。

## 2. 看的顺序（按"信息密度"排，不是按目录顺序）

1. **README** —— 这项目是干什么的、支持哪些板子、有什么坑
2. **`config.json` / `config.h` / `sdkconfig.defaults`** —— ⭐ **硬事实都在这**
   - 板级 `config.h`：引脚是写死的常量（`#define AUDIO_I2S_MIC_GPIO_WS GPIO_NUM_4`）
   - 板级 `config.json`：这个变体默认开哪个屏/走哪个编译配置
   - `sdkconfig.defaults`：**芯片的硬指标**（Flash 大小、PSRAM 模式、唤醒词模型）
3. **`docs/` 目录** —— 协议、接入方式（比 README 细，比源码好读）
4. **`releases` 的 assets** —— 有没有预编译产物。**有就不用装工具链**（这次就是
   发现有现成的 `bread-compact-wifi-lcd` 固件，直接省掉了装 ESP-IDF）
5. **真要看代码**：`git clone --depth 1` 到本地，用 `rg` 搜 —— **比在网页上点快十倍**
   （GitHub 的网页版 code search 要登录，浅克隆不需要）

## 3. 一条元规则：**以代码为准，不以教程为准**

这次有两个反面例子，都是"常识/教程"会把我们带沟里：

- 「2.4 / 2.8 寸 240x320 的 SPI 屏基本都是 ILI9341」—— 谣言级的常识。实际得看
  上游 `config.h` 支持哪些驱动、预编译固件用的是哪个；我们最后是**按驱动选屏**，
  不是按尺寸选屏。
- 「ESP32-S3 开发板随便买」—— 实际固件里写死了 `FLASHSIZE_16MB` + `SPIRAM_MODE_OCT`，
  买到 N8R2 直接刷不进去。

**规矩**：凡是"买什么、接哪根、能不能跑"这类问题，答案只能来自仓库里的
`config.h` / `sdkconfig` / `docs/`，不能来自别人的博客或想象。

## 4. 想让 AI 帮你查上游，一句话就够

> 「读 <仓库地址>，我要实现 <某件事>。先告诉我：它支持哪些硬件变体、引脚/协议在哪个
> 文件里、有没有预编译产物、我们缺什么。**给我文件名和原文，不要总结成散文。**」

最后那句是关键：**要文件名和原文**，你才能自己复核，AI 编不了。
